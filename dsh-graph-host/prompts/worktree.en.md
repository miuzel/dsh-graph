【Mandatory worktree isolation】This task must by default be completed in an independent worktree: the dedicated worktree is pre-created by the supervisor, or created by the plugin at dispatch time (prepareAttemptWorktree, with the naming convention .worktrees/g-<goal-number>-att-<NN>, a same-named branch, and the baseline commit of this dispatch as the base); the actual worktree path is given by the attempt record / dispatch brief. The subagent works directly in the given worktree, **and must never independently create a tree, create a branch, switch branches, or modify branches**. Code changes, tests, and generated files may occur only in that worktree; **main is the read-only published branch, and directly modifying main or another target branch is forbidden; independently bypassing isolation on the grounds of a "simple change" is also forbidden**. After completion, commit in the worktree and wait for supervisor review; the supervisor merges into the current version integration branch (such as <version>-test).
【The sole exception】Only when the supervisor explicitly writes `worktree=false` and the reason in this dispatch's attempt brief may the independent worktree be exempted; the supervisor handles small changes such as documentation/long-term memory itself, and subagents may not apply the exception on their own. Even with worktree=false, the main branch remains absolutely read-only; directly modifying main is forbidden.
【Worktree naming convention】Attempt worktrees uniformly follow the .worktrees/g-<goal-number>-att-<NN> convention, and branches use the same suffix (for example g-125-att-03, g-163-att-03), eliminating ambiguity and branch conflicts.
Division of data: code changes go in the worktree; board data .dsh-graph/ is still written in the main worktree (graph_* tools write the main worktree's board/event stream, not isolated by worktree branches, to avoid state drift).
