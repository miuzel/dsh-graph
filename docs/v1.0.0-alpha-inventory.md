## 4. 明确不可直接合入的回退面

- **质量门禁**：两分支相对基线均缺 232 个顶层 `.test.ts`；包括整套件自证/嵌套 runner、隔离、当前 care/keepalive、真实 host 鉴权/复用等测试。不得为了保留试验而删减现有 suite。
- **核心模块**：相对基线缺 `core/care.ts`、`keepalive.ts`、`platform.ts`、`review-policy.ts`；[当前依赖图](<v1.0.0-recon.md>) 证明这些是已用能力，不是可以清理的遗留。
- **构建/发布**：缺当前 `scripts/build.sh`、`scripts/run-tests.mjs`、reporter 和平台门禁，重新将 host/core JS 与合并 client JS 放回源码目录；不能替换独立 dist 和原子发布。
- **用户功能/文档**：相对差异缺 batch-accept、board-retain、module/help/narrow-width 等客户端源模块，以及多版发布/平台说明。不能用 Pi TUI 新功能抵消 DSH 已发布功能缺失。
- **依赖/兼容**：旧 manifest 的 host range、peer/runtime dependencies、workspace/锁文件和 prepack 不得进入此次设计 commit；不能宣称“core 相同”即可让两个宿主安全并发写。

## 5. 采纳方式与边界

只采纳“端口显式化、命令元数据、初始化不隐式写、审批 revision 复核、派发准入先行、负向测试主题”等**设计输入**。没有任何试验实现被批准合入。本轮既不 merge 也不 cherry-pick；将来如确需代码复用，应基于 80feee1 之后的现行集成线逐项重写/移植并重验，而非把旧整树当新基线。

负责人需先确认 [接口与首个纯提取范围](<v1.0.0-public-contract-draft.md>)；当前不存在“Pi 已跑通所以五宿主接口已冻结”的证据。分支记录不产生新任务，也不授权修复历史试验。
