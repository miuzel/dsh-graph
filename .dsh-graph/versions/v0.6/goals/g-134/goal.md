## 目标描述


为版本泳道补齐完整管理能力：创建版本泳道、重命名版本泳道、删除空版本泳道。仅管理版本泳道；backlog 与独立目标不是可删除/改名的版本泳道。

执行顺序：v0.6 阶段 B，依赖 g-142 的客户端模块边界稳定后开始；完成后为 g-135 的发布操作提供统一版本元数据与看板入口。

实现约束：所有持久化变更事件先行；版本元数据、目标归属与看板投影保持一致；删除只允许没有任何目标（含归档目标）的空版本；重命名需保持目标目录、版本引用与事件可追溯；破坏性 UI 操作必须二次确认。


## 质量判据

1. 可在看板中创建版本泳道并持久化版本元数据；新版本可接收目标并在重载后仍正确显示。
2. 可重命名版本泳道，版本目录、目标 `version` 引用、看板投影与事件记录保持一致且可追溯。
3. 只能删除完全空的版本泳道（含归档目录在内均无目标）；非空版本必须拒绝删除并给出原因；backlog 与独立目标不暴露为版本管理对象。
4. 创建、重命名、删除均遵守事件先行；破坏性删除操作有 UI 二次确认；覆盖成功/拒绝路径的测试与 `node --test core/tests/*.test.ts` 全量通过。
