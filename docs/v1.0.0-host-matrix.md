## 缺能力的降级，不伪造对等

1. 无执行端口：仅人工维护/查询看板；start/review/collect 自动执行拒绝，不造 child 或默默改主树。
2. 无可信身份：仅显式允许的只读路径；claim/写入/审批拒绝。不能用 prompt 自述弥补授权。
3. 无观察/输出：不自动判停/复用/解绑，不以 idle 推断任务完成；允许主管按原授权补结果。
4. 无确认 UI：需要 Human Gate 的动作停下由负责人在可信渠道处理，不自动 grant/force。
5. 无 Web UI：文本投影是候选，不假装已有 UI，不删 DSH Web 功能；无 care/keepalive 不影响 core。
6. 本地文件/Git 无法核实：不承诺事实互写或执行隔离；不以 MCP、宿主品牌或版本范围推断权限。

## 待实测计划（设计计划，不在本轮执行）

对每个选定宿主固定产品/版本、CLI/插件/SDK 模式、OS、sandbox、工具注册机制及官方文档版本；把来源记录为 docs/source/运行 probe 三类。没有运行证据仍标 ?。

最小 probe 清单：可信身份不可伪造；workspace 与 graphRoot 分离；只读不 init/claim；工具参数/错误与 DSH 相同；创建人工目标并保持原状态边；如宣称执行支持，验证 start→bind→output→review、晚到/重复通知、取消未停止、重启 registry unknown、闲置复用和投递失败。审批缺失/假身份/无隔离必须拒绝且无新事实副作用。

MCP 另外测试实际 client 的 schema 支持/错误表示、连接重连与重复调用、取消请求和 execution 的差异、server 本地 root 权限；不要求 server 自带代理。不导入新 SDK 依赖以“证明”设计，具体实现须另行授权。
