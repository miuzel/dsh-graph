【强制 worktree 隔离】本次任务必须在独立 worktree 中完成：专属 worktree 由 supervisor 预建、或由插件在派发时创建（prepareAttemptWorktree，命名约定为 .worktrees/g-<goal-number>-att-<NN>，分支同名，基线为本次派发基线 commit），实际 worktree 路径以 attempt 记录 / 派发说明为准；**绝不自行拉树、建分支、切分支、改分支**。代码改动、测试及生成文件只能发生在该 worktree；**main 为只读已发布分支，禁止直接修改 main 或其他目标分支，也禁止自行以「简单改动」为理由绕过隔离**。完成后在 worktree 提交，等待 supervisor 复核；由 supervisor 合并到当前版本集成分支（如 <version>-test）。
【cwd 事实】你的 cwd 是主/集成工作树，不是你的工作树。即：被派发的子代理，其 shell 与文件工具的默认 cwd 落在仓库根（主/集成工作树，即 <仓库根绝对路径>），而**不是**上面那个 .worktrees/g-<goal-number>-att-<NN>。这是**预期行为**、不是故障：看板数据 .dsh-graph/（目标、卡片、事件流）必须写主工作树，把 cwd 改到 worktree 会让看板根漂移到 <worktree>/.dsh-graph 并造成状态漂移，因此派发不会替你切换 cwd。**但 cwd 在主工作树绝不代表可以在主工作树改代码**——工具默认落在 cwd，不留神就会直接在主工作树里改（这正是并发串扰事故的形态）。
【你的工作树在哪 / 如何核实】命名约定 .worktrees/g-<goal-number>-att-<NN> 相对仓库根（即你的 cwd）解析，可据此拼出绝对路径；**动手前必须先核实真实路径**：运行 `git worktree list`（或 graph_list_worktrees）确认本次 goal/attempt 对应的工作树路径与分支，并以 attempt 记录 / 派发说明中的路径为准。提示词是静态资源，**不含**本次 worktree 的绝对路径（真实路径只写在 attempt 记录里），任何自行假定的路径都无效，一律以核实结果为准。
【操作纪律】所有代码改动、测试执行与 `git` 提交都必须发生在该 worktree 内：先 `cd <绝对路径>` 再操作，或对每条命令显式使用 `git -C <绝对路径>`（读写文件也要用 worktree 内的绝对路径，不要依赖 cwd）。**禁止在主工作树产生任何代码改动**（含未提交改动）。看板数据 .dsh-graph/ 仍由 graph_* 工具写主工作树，这是唯一允许落在主树的写入，不得以此为理由在主工作树改代码。
【唯一例外】仅当 supervisor 在本次派发的 attempt brief 中明确写出 `worktree=false` 与理由时，才允许豁免独立 worktree；文档/长期记忆等小修改由 supervisor 自己处理，子代理不得擅自套用例外。即便 worktree=false，main 分支仍绝对只读，禁止直接修改 main。
【worktree 命名约定】attempt 工作树统一遵循 .worktrees/g-<goal-number>-att-<NN> 规范，分支使用相同后缀（例如 g-125-att-03、g-163-att-03），消除歧义与分支冲突。
