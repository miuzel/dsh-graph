## 交回报文骨架（尾注·逐项必填：缺项即视为交付不完整）

本报文是完成摘要（results.md）的主要素材：**越规范，摘要越可信**。请逐项作答，标题逐字使用（便于机读）。
（评审子代理的报文另有其专属骨架，不在此列 —— 执行者只需回答下面 6 项。）

### 执行者报文（6 项逐项必填）
1. **交付位置与改动**：worktree / 分支 / commit / 基线，以及按能力分组的文件 + 模块清单（每个文件一句「加了什么」）。
2. **怎么改的**：关键设计 / 数据流 / 为什么这样做（含被否方案与否决理由）。
3. **影响面**：谁受影响（运行环境 / 其他目标 / 发布含义 / 兼容性 / 配置迁移）。
4. **测过什么 / 没测什么**：命令 + 单行证据（含**负向对照**与**基线对照**）；未验证项及原因。
5. **残余风险与判据对应**：风险 / 残余 / 已知缺陷（每条一句）+ 每条判据 → 达成与否 + 证据指向。
6. **需主管裁决事项**：逐条列出（附默认建议）。

### 报文长度预算（软上限；超限不算交付失败，但必须自报）
- 报文本体软上限 {{soft_max_kib}} KiB（落盘仍为 64 KiB、读取 1 MiB：**历史留档完整，只省喂给 LLM 的那一份**）；
- 分预算：**交付位置与改动 ≤1.5 KiB**；**怎么改的 ≤1 KiB**；**影响面 / 测过什么没测什么 / 残余风险与判据对应 各 ≤0.5 KiB**；其余每项一行；
- 超出软上限时，在报文**末尾**自报一行：`已超预算：<实际字节>/4 KiB`（**不删证据、不省略未验证项、不砍判据对应**）；
- 送 LLM 摘要的输入有硬上限：每 attempt 8 KiB（头 4 KiB + 尾 2 KiB + 中段省略标记）、单次总预算 256 KiB ⇒ 写得紧凑才不丢信息；被省略的字节数会由写入器标注在摘要里。
