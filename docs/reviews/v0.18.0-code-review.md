### C1：解绑绕过旧 running child

**定位**：[仅检查当前 binding](/home/miuzel/workspace/personal/dsh-graph/core/ops.ts#L7557-L7570)；[批量 supersede 旧 attempt](/home/miuzel/workspace/personal/dsh-graph/core/ops.ts#L7634-L7671)。

**触发**：同一个目标有旧 attempt 的 child 正在 running，最新 attempt 的 child 已 idle；对最新 binding 调用合法解绑。目标处于 in_progress 时可继续派发，故多 attempt 不需要恶意输入才能产生。

**实际**：liveCheck 只查询最新 child；旧 child 被直接清除绑定并标记 detached/superseded，随后暂缓操作可以搬走目标目录。旧 child 并未停止。另一个审计问题：旧 child_id 删除后才构造事件，事件中的 child_id 变为 null。

**影响**：看板不再保护真实运行者；旧任务继续使用已迁移的目标数据或提交成果时，关联与状态失真。

**最小修复**：默认只解绑精确选中的 attempt。若确需清理旧绑定，逐项 liveCheck；running/unknown 拒绝，保留原 child_id；所有预检通过后再写。不要把“被新 attempt 取代”等同于“子代理已停止”。

**验收**：最新 idle、旧 running／unknown 时，旧 binding 不变且暂缓拒绝；旧 idle／gone 时才可显式清理；事件保留原 child_id。

### C2：失败等待者误删外部锁

**定位**：[withTx 失败分支](/home/miuzel/workspace/personal/dsh-graph/core/transaction.ts#L139-L164)，[releaseLock 无条件删除](/home/miuzel/workspace/personal/dsh-graph/core/transaction.ts#L125-L129)。

**触发**：另一个存活进程占用锁，本调用获取超时；或者同进程嵌套获取同锁被拒。

**实际**：catch 无条件 releaseLock，即使 acquireLock 从未成功；锁文件被删除，后来的进程可以进入仍受原持有者使用的临界区。

**最小修复**：维护 `acquired` 标记，只释放本次成功取得的锁；增加持有者／token 检查。若继续支持死 PID 的锁回收，不用直接 `flag:'w'` 覆写作为独占获得锁的证明。

**验收**：超时／嵌套失败后原锁仍在；实际两个子进程竞争时临界区不重叠。现有[“并发锁”测试](/home/miuzel/workspace/personal/dsh-graph/core/tests/transaction.test.ts#L153-L186)只是同步 for 循环；[嵌套测试](/home/miuzel/workspace/personal/dsh-graph/core/tests/transaction.test.ts#L189-L225)未断言外层锁仍存在。

### C3：事件失败，但修改已落盘

**定位**：[transition 先 saveGoal 后 appendEvent](/home/miuzel/workspace/personal/dsh-graph/core/ops.ts#L1968-L1975)；[writeSupervisorSession 回调内先 atomicWrite](/home/miuzel/workspace/personal/dsh-graph/core/ops.ts#L414-L427)；[withTx 在回调返回后才 appendEvent](/home/miuzel/workspace/personal/dsh-graph/core/transaction.ts#L145-L153)。

**触发**：只对事件追加注入 EIO；原事件历史与目标文件仍可正常读取／写入。

**实际**：调用报告失败，但目标状态已是 collecting、主管绑定也已写入；rebuild 检出 frontmatter 与事件重建结果不一致。

**影响**：失败结果不能代表无副作用，重试、交接与对账缺乏可信依据；与仓库声明的“事件先行”契约直接冲突。

**最小修复**：先修这两个高频写点；将事务回调拆成“计算计划”与“持久化”阶段，使 helper 能控制事件与文件顺序。明确事件先行只提供可恢复审计，不等于跨文件原子事务；文件写失败时给出可诊断状态，避免用“事务”掩盖部分成功。无需引入数据库或通用复杂回滚系统。

**验收**：事件追加失败时文件不变；事件成功、文件落盘失败时保留明确恢复证据；正常流程事件与文件一致。

### C4：合法围栏破坏描述

**定位**：[normalizeDescriptionHeadings](/home/miuzel/workspace/personal/dsh-graph/core/ops.ts#L208-L224)。

**触发**：四反引号围栏中包含三反引号示例。这是正常 Markdown，常用于展示代码围栏语法。

**实际**：遇到任意三字符以上围栏就翻转布尔值，忽略围栏字符种类、开启长度与关闭规则；代码中的 `##` 被改成 `###`，真正外部 `##` 却未降级，后续小节解析截断目标描述。

**修复**：复用或统一已有 fence-aware 扫描，记录 fence 字符和开启长度；关闭必须满足正确类型与长度。验收覆盖四／三反引号、波浪号、混合围栏、缩进与普通标题。不要为这一个问题引入完整 AST 框架。

### H1：失败投递显示已送达

**定位**：[promptSessionQueue 三个分支](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/lib/client/session-hooks.js#L28-L64)；[润色入口据 true 显示已投递并跳过复制兜底](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/lib/client/goal-actions.js#L179-L196)。

### H2：目录迟到，会话永久未接入

**定位**：[Hook 的 started 与 effect 依赖](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/lib/client/session-hooks.js#L205-L225)。

**触发**：首次渲染时目录尚无 child，解析地址返回 null；随后目录更新，child 出现。

**修复**：将“等待目录”与“已保留成功”分开；目录变化只唤醒尚未成功且没有请求在飞的 entry。**不能简单把 listSnap 塞入原 effect**，否则 retain 发布快照可能造成自身重触发。测试晚到目录、刷新失败恢复、多消费者及只 retain 一次。

## 二、可优化、简化的内容

### core：按领域拆分，而不是增加框架

1. **拆大文件但保持 facade**：[ops](/home/miuzel/workspace/personal/dsh-graph/core/ops.ts) 10,122 行，占 core 顶层源码 14,120 行的约 72%。它同时包含配置编辑、生命周期、共享卡、附件、角色提示词、摘要、记忆等。建议按这几类逐步抽取，原导出保持不变，避免一次性全库改调用方。
2. **写入顺序统一**：当前 “withTx” 回调可自行持久化，helper 无法兑现其注释中的阶段顺序；另有普通 appendEvent、withMemoryLock、不同 atomicWrite 路径。优先统一高频状态变更和错误分类，再考虑收敛写入 helper。C2/C3 比抽象美观更重要。
3. **配置读写尽量结构化**：项目已经依赖 YAML，但同时保留多套按缩进／正则读写。保留注释有价值，不建议换成裸 stringify；可统一用已有解析／Document 能力，并逐步迁移实际高频字段，减少同一配置在多个消费者中不一致。
4. **活跃状态统一判定**：core 暂缓／删除、worktree 清理、客户端有各自 result/status 判定。统一“已结束”与“仍运行／不可确认”的契约；不要将人话 status_line 用作真实运行者已停止的充分证据。

5. **缓存周期与轮询不匹配**：[watcher idle TTL](/home/miuzel/workspace/personal/dsh-graph/core/cache-state.ts#L8-L20)仅 500ms，GUI [轮询默认 15 秒／最低 5 秒](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/lib/client/helpers.js#L251-L254)。普通下一次轮询前 watcher 已关闭重开，[epoch 变化必须执行 payloadFactory](/home/miuzel/workspace/personal/dsh-graph/core/cache.ts#L30-L43)，最后仍可能返回 fromCache=true。这个标记不等于避免重建投影。优先让 TTL 覆盖典型刷新间隔，保留 unref、数量上限与断档 rescan；没有大看板基准，不能声称具体延迟收益。

### 插件：减少平行流程

1. [宿主入口](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/index.js) 4,475 行：保留 apply 为组合入口，抽出 execution／collection／summary 服务，REST 与 graph 工具复用同一入口。已有 execution 统一派发可当先例；H3 表明 collection 仍有分叉。
2. **能力适配集中**：客户端 using／retain／legacy 分支必要，但成功回执、订阅、ready／release 应在一个适配层完成，调用方不再重复猜宿主版本。
3. **复杂组件小步拆分**：[kanban](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/lib/client/kanban.js) 3,408 行、[goal-modal](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/lib/client/goal-modal.js) 1,947 行；按数据选择、动作、布局拆分即可，不必改用新状态管理库或大 UI 框架。
4. **正确性测试优先于字符串守卫**：真实竞争、目录晚到、错误回执、spawn 成功 bind 失败、事件 EIO 的测试比逐字匹配实现片段更能保护用户行为。

- [指南行数下限／中英逐行相等测试](/home/miuzel/workspace/personal/dsh-graph/core/tests/prompt-i18n-parity.test.ts#L27-L42)会阻碍删冗余。保留关键约束／工具参数／双语语义对等测试，不把长篇幅本身当质量。
- **历史目标号驱动的契约膨胀**：大量 g-xxx 注释与文本锚点有审计价值，但不应长期要求每次重构维持旧实现字面形态。历史细节移到变更记录，源码只留原因、当前不变量与兼容边界。
- **静默降级太宽**：可选宿主服务缺失可以降级；实际启动／绑定／写入失败应有可见结果。不要为了“绝不影响宿主”吞掉关键错误，H1/H3 就是反例。

### 应保留的复杂度

workspace 隔离、路径／symlink 基线、真实 worktree、构建暂存与原子发布、有限本地锁、人工裁决边界、结果归档与来源标记均有明确收益。本次不建议删这些，也不建议把磁盘 Markdown+事件记录重写成数据库系统。

### 4.2 应消除的语义冲突

1. **claim 授权**：[hint](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/prompts/guide-hint.zh.md#L2)要求人类明确授权才 claim；[主管指南](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/supervisor-guide.zh.md#L13-L25)又在未配置／未指向当前会话时直接要求 claim，只在“已指向其他会话”时强调防争抢。统一成“加载 skill 不构成授权；无主管配置也先取得授权”。
2. **谁迁移状态**：[阶段推进](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/supervisor-guide.zh.md#L81-L101)要求主管立即推进；[执行规范](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/supervisor-guide.zh.md#L292-L300)又说主管不要代劳。改成明确分工：派发入口负责准入与 in_progress；executor 负责真实进展／review；主管负责负责人裁决／异常收口。
3. **迁移拒绝后能否继续**：[主管指南](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/supervisor-guide.zh.md#L292-L298)说被拒后保留汇报继续工作；[实际执行纪律](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/index.js#L631-L638)说立即停止。涉及门禁，应统一为失败停下，解释后再授权／修正。
4. **隔离默认事实**：工具说明／指南强调强制默认，实际[类型默认](/home/miuzel/workspace/personal/dsh-graph/core/worktree.ts#L170-L183)对 clean patch／chore／task 不隔离；派发[isolation 决策](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/index.js#L1524-L1541)又包含 cleanliness 回落。明确说明实际默认与人工豁免，不让 Agent 在几份文字中选择。
5. **graph cwd 与代码 cwd**：[worktree 指南](/home/miuzel/workspace/personal/dsh-graph/dsh-graph-host/prompts/worktree.zh.md#L2-L4)称移 cwd 会导致数据根漂移；[收集 prompt](/home/miuzel/workspace/personal/dsh-graph/core/ops.ts#L4879-L4883)要求在当前 worktree 跑 graph。core 已有 canonical root 解析，不应靠互相矛盾的静态文本解释；直接注入本次 code workspace 与 graph root 两个权威路径。
6. **结果内容与证据格式**：要求交付“只写一行概要”又要求完整报文骨架／改动影响说明。统一为“测试证据用单行；交付正文用结构化 Markdown，可正常解释原理和风险”，不把日志禁令扩张成不许写正常报告。
7. **只读 reviewer／collector 的工具能力**：minimal 角色仅有 read/bash 等有限工具，但全局指令要求 glob/grep、且不用 shell cat/rg。先让可用工具与提示词一致；不要要求 Agent 履行被过滤掉的工具契约。

### 4.3 推荐收敛方案

- **常驻最小化**：全会话 hint 留能力入口、默认普通会话、claim 授权边界；结果摘要操作详情移到工具说明／skill。
- **一套角色纪律源**：按角色＋语言维护短模板；attempt 与 persona 引用同源，不要求手工维护多份“相同口径”。未接线角色明确 reserved。
- **单次 prompt 带真实事实**：既然 prepareAttemptWorktree 已得到实际路径，派发就注入该路径、graph root、实际 mode、真实工具清单，不再让 child 按静态资源猜位置。
- **结构化字段严格区分**：当前 brief/directive 是 action，handoff/cards 是参考，这一方向保留；避免重复解释同一优先级数遍。
- **全文最终装配测试**：覆盖 zh/en × standard/minimal × worktree/no-isolation，以及记忆字面量 `{{…}}`、空字段、目录晚到。自动检查语言和工具可达性；人工抽样判断矛盾，不靠逐行相等代表语义相等。
- **成本只报实测**：统计最终系统 prompt、tool schema、skill、单次任务文本的字节／真实 tokenizer token。没有延迟／成本对照实验，不承诺 token 或延迟收益百分比。
