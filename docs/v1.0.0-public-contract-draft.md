# 公共契约 v1 草案（未批准）

[返回 recon](<v1.0.0-recon.md>)。本契约是设计讨论输入，不是 0.24.0 已实现 API；不新增工具、不更改磁盘格式。关键词“必须”描述拟议约束，实施前需负责人确认。

## 1. 三个版本轴与协商

- `contractVersion = "1.0-draft.1"`：应用端口/能力描述的草案版本，不等于 npm 发布号，不落入旧事实文件。
- `storageProfile = "dsh-graph/0.24-compatible"`：既有文件兼容配置标签，仅在能力响应中声明，不补写存量数据。
- `adapterVersion`：适配器自己的版本；不得用宿主版本号推断能力。
- 草案阶段不承诺稳定；冻结后同 major 只加可选字段/可选能力，删除/必填变化/语义改变升 major。存储迁移与契约升级分开审批。
- 不支持的 major 写入前拒绝；只读若也不能安全理解，不伪装成功。协商不能隐式初始化、改写或“升级”项目。

## 2. 数据模型（逻辑视图，不另建事实源）

[当前解析器](<../core/model.ts#L38-L82>) 接受 `meta: Record<string, any>` 与正文；[Schema](<../schema/SCHEMA.md>) 是历史说明与约束索引，具体字段以基线实现为准。新视图不得以封闭 DTO 丢掉旧字段。

| 逻辑实体 | v1 拟暴露字段/约束 | 既有兼容边界 |
|---|---|---|
| Goal | id、title、type、status、description、criteria、placement、relations、contextCards、metadata | ID 不改写/不复用，包含历史随机 ID；目录决定归属，version 冗余同步；正文/未知 meta 保留 |
| Criteria | ordered items + confirmed + rulesSnapshot | 不新造 criterion ID；保留既有 Markdown 提取与 `✅已验` 识别；确认事件是独立 guard |
| Placement | backlog / standalone / version + slug + archived | 不将 placement 当状态，不改目录或用户根路径 |
| Relation | type + targetId；dependsOn 分列 | 既有 supersedes/amends/extends/related 与依赖环规则不变，不把 depends_on 搬入 relations |
| Card | id、scope、title、status、body、summary、attachmentRefs、binding | shared 默认、goal 显式；empty/collecting/filled/reviewed；引用/收集中的删除门禁保留 |
| AttachmentRef | safe relative name + optional media metadata | 仍用 `@att/<name>`；路径穿越/链接/仍被引用时删除拒绝 |
| Attempt | id、goalId、statusLine、state、result、baselineCommit、worktree、binding | 领域完成与宿主 idle 分开；不从 brief 猜 baseline/source/acceptance；旧 child_id 等字段保留 |
| Binding | adapterId + opaque executionId/sessionId + parent + generation/lease（可选） | 新字段是否落盘待裁决；DSH 继续按既有 token/代际验证，不信工具自报 child |
| Review / Result | goalId、attemptId、candidate/base commit、verdict/source、contentRef | reviewer 无 delivered 权；保留 reviews 与 results 现有布局和来源字符串 |
| Memory | id、kind、scope、text、sourceRef、audit provenance | memory/memory.jsonl 单一真源，standing 授权不降级 |
| BoardSnapshot | revision、generatedAt、goals/versions、optional diagnostics | 只读派生投影；cache 非事实；原 DSH 返回形状不因新 DTO 改变 |

状态仍为 draft/planning/collecting/ready/in_progress/review/delivered/blocked，边和 guard 完全委托 [machine](<../core/machine.ts#L10-L89>) 与 ops。禁止把“支持 runtime”设为创建/人工维护目标的前提。未知状态不归一成 delivered；错误返回保留诊断。

## 3. 事件与通知

既有磁盘 [GraphEvent](<../core/events.ts#L9-L15>) = `{ts, actor, event, goal?, details}`；继续 append-only、保留已有本地时区偏移，不批量补 eventId 或重排历史。

拟议只读事件信封（不覆盖磁盘记录）：

```ts
type EventViewV1 = {
  contractVersion: "1.0-draft.1";
  cursor: string;             // store 提供的 opaque 顺序位置，不是时间戳
  record: { ts: string; actor: string; event: string;
            goal?: string; details: Record<string, unknown> };
};
```

- 游标只供单一 graphRoot 的分页/重放，不承诺跨库全局顺序，不拿秒级 ts 去重。
- 已有 event 名及 details 原样保留；新投影遇未知事件保留可查询原记录，不以其驱动已知状态，不静默丢审计；损坏行显式报错。
- 修改继续先走既有事务/事件先行，成功后投影；不把“追加事件成功”夸大成“所有文件已完成”，失败交既有恢复路径，禁止手工补成功事件。
- 执行通知是 adapter 的可信输入，不是任意 tool 参数：`started / progress / ended` 必须关联真实绑定、代际/租约及 attempt。结束未知、空输出或重复/旧代通知不得生成 PASS；继续既有结果占位与来源兼容。
- 不承诺 exactly-once；同一通知重投需按绑定与既有幂等规则处理，无法确认时返回 unknown。是否为所有宿主新增持久通知 ID 是负责人裁决，不在本轮引入。

## 4. 存储端口

拟从现有实现封装 `readGoal / listGoals / readEvents(cursor) / snapshot / executeMutation`，而非暴露任意 `writeFile` 给宿主。`executeMutation` 必须使用现有 schema、锁、CAS、提交/恢复，不让 adapter 自行拼接事件和 frontmatter。

- 保持 `.dsh-graph/`、backlog/standalone/version/archived、cards/shared pool、attachments、memory、attempts/reviews/results 布局；用户自定义 root 与 scratch 边界不变。
- graphRoot 与 executionWorkspace 显式分离。DSH 相对 root 在 linked worktree 回主树，scratch 不回主树；绝对覆盖不触发 Git 发现：[root 依据](<../core/root.ts#L7-L29>)。其他宿主不得靠 process.cwd 猜当前看板。
- 文本保留非受管区域、未知字段和 YAML 注释；文件格式兼容不意味着多宿主并发互写已验证。
- Node 文件适配复用 [transaction](<../core/transaction.ts>) 与 [platform](<../core/platform.ts>)；不新增数据库/锁库/事件服务，也不声称浏览器可直接运行 Node core。
- 未初始化查询报告未初始化，绝不自动 init/claim。异步审批期间 revision 变化重新校验，不能在过期审批后提交。
- worktree 的位置隔离不等于权限隔离。缺 Git/隔离能力时，需隔离的派发拒绝，不自动回退主树。

## 5. 命令/工具端口

拟议内部 `execute(commandName, args, trustedContext)`；外部 DSH 仍暴露现有 `graph_*` 工具名、参数、默认值、返回值、错误形态及 REST 路由。公共命令目录从当前基线提炼，不采用 alpha 的 39 工具旧快照。

```ts
type TrustedContextV1 = {
  actor: { id: string; kind: "human" | "agent" | "system" };
  adapterId: string;
  workspace: string;
  graphRoot: string;
  delegatedScope?: { goal: string; attempt?: string; card?: string };
  // 身份、授权和审批凭据由可信 adapter 注入，绝非工具可填字段。
};
```

命令目录条目拟含 name、inputSchema、outputSchema、readOnly、requiredCapabilities、authorizationPolicy、documentedIdempotency；这些是文档/测试契约，不作为新增运行时依赖。按命令的实际副作用标 readOnly，不因名字叫 query/rebuild 就假定只读。

| 命令组 | 继续保持 | 适配器责任 |
|---|---|---|
| 查询/校验/设置读取 | 现有语义与默认值；派生数据标记来源 | 只读不触发 init/claim，不隐藏读取错误 |
| 目标/判据/卡片/关系/版本/记忆修改 | 原状态/引用/授权/事件/幂等规则 | 可信 actor、参数校验、原门禁，不替 core 决策 |
| start/reuse/review/collect | 准入先行、基线锚点、绑定和结果归因 | 必需能力缺失即拒绝；异步投递不确定不能自报成功 |
| accept/delivered/删除/清理 | 既有 Human Gate、Git 真源及权限规则 | 不能由 reviewer 或工具自报 human 绕过 |
| supervisor claim | 仅显式负责人请求 | 无会话身份/无授权时不自动接管 |

不统一所有写操作为“每次必须 UI confirm”：这会改变现有 DSH 授权语义。新宿主没有确认 UI 不是默许；遇必需人工 gate 则停止，提供人工后续步骤。人工凭据来源/有效期由负责人另行冻结。

## 6. 能力探测

拟议 `describeCapabilities()` 是只读内部端口（非新增 DSH 工具承诺）：

```ts
type CapabilityV1 = {
  status: "supported" | "unsupported" | "unknown";
  available: boolean;         // 当前服务/权限是否就绪；未知一律 false
  evidence?: { source: string; checkedAt: string; hostVersion?: string };
  limitations?: string[];
};
```

候选 keys：`identity.trusted`、`tools.register`、`storage.localFiles`、`git.worktree`、`execution.start`、`execution.resume`、`execution.cancel`、`execution.observe`、`execution.finalOutput`、`approval.human`、`prompts.inject`、`models.catalog`、`ui.board`。声明支持 ≠ 服务当前可用 ≠ 本会话授权 ≠ 真机验证通过；adapter 须分别核验。配置开关不能伪造能力，方法存在也不能证明取消成功。

`liveState = running | idle | gone | unknown` 延续现有 [ExecutionLiveCheck](<../core/ops.ts#L11851>)。unknown 不视为 gone，不清理绑定，不强制复用，不将静默等同卡死。特性需要的 key 缺失/unknown/available=false 一律拒绝该特性，但不影响无关只读/人工看板功能。详见 [矩阵](<v1.0.0-host-matrix.md>)。

## 7. 错误、取消与兼容

拟议内部 Result 是 `{ok:true,value}` 或 `{ok:false,error:{code,message,retryable,details?}}`。不要将新 Result 包一层直接破坏 DSH 当前工具返回；由 adapter 映射。

| 拟议稳定 code | 语义/重试规则 |
|---|---|
| E_INPUT / E_UNKNOWN_COMMAND / E_VERSION | 参数、命令或协议不支持；修正输入，不盲重试 |
| E_NOT_INITIALIZED / E_NOT_FOUND | 事实未初始化/对象不存在；禁止自动创建 |
| E_IDENTITY / E_FORBIDDEN / E_APPROVAL_REQUIRED | 缺可信身份、权限或人工授权；不由模型补字段自证 |
| E_CONFLICT / E_BUSY | CAS 冲突/锁占用；重新读取后有限重试，不 force 默认覆盖 |
| E_CAPABILITY_UNAVAILABLE | 能力未支持/未知/不可用；返回缺失 key，无静默降级派发 |
| E_STORAGE / E_CORRUPT | 持久化或损坏；报告恢复状态，不承诺无副作用后盲重试 |
| E_CANCELLED / E_DELIVERY_UNKNOWN | 已确认取消/投递结果不明；后二者不可混淆，未知先对账绑定 |

保留 GraphError / GraphConflictError 与原 HTTP 400/409 等兼容映射；公开错误不得泄露凭据。取消请求不等于进程已停，执行结束不等于目标 delivered。统一幂等键和跨宿主事务暂不引入，避免以接口美观扩大产品语义。

## 8. 必须由负责人裁决（未裁决停在设计层）

1. **公共导出/包边界及首提取范围**：建议先 model+machine，原路径委托兼容；不立即发布独立 npm 包。
2. **身份与 Human Gate**：建议 DSH 原行为不变，其他宿主必须可信注入；审批凭据和无 UI 人工路径另立契约，不采纳 alpha 的全写确认策略。
3. **跨宿主绑定落盘**：建议本阶段不写 adapter/generation 新字段，不把旧 session ID 加前缀；设计通过后再评估冲突与迁移。
4. **事件/存储版本**：建议 v1 仅外层协商，旧日志不补字段不重放改写；重放未知事件的诊断策略需确认。
5. **第二宿主与 MCP 定位**：建议先选一个有可核实身份/执行端口的宿主独立验证；MCP 只提供传输，不承诺代理生命周期。
6. **兼容验收与回滚**：建议源码/工具/磁盘黄金样本 + DSH 全量原 suite + 跨平台门禁；新宿主互写未实测不得宣称可互换。

确认以上接口草案、边界和最小范围之前，不执行实现。负责人不同意某项时，修订本文，而不是修改产品以证明草案。
