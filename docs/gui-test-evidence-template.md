# GUI 测试证据模板（g-298 首次派发）

## 证据条目结构

每个证据条目必须包含以下字段：

### 1. 基本信息
- **证据 ID**: `EVID-YYYYMMDD-NNN`（日期+序号）
- **关联目标**: `g-XXX`
- **关联候选**: `commit: <sha>` 或 `pr: <number>`
- **测试环境**: 
  - 浏览器: `Chrome/Firefox/Safari` + 版本
  - 视口: `<width>x<height>` (如 `1920x1080`, `375x667`)
  - 操作系统: `Windows/macOS/Linux`
  - 测试实例: `port 3082`（隔离测试环境）

### 2. 场景定义
- **场景类型**: `drag | fold | lazy-load | refresh-reopen | narrow-viewport`
- **场景描述**: 一句话说明测试场景
- **前置条件**: 测试前需要的状态（如：目标已创建、卡片已填充）

### 3. 操作序列
```
1. 步骤1描述
2. 步骤2描述
3. ...
```

### 4. 预期行为
- 期望的 UI 状态或行为

### 5. 实际行为
- 实际观察到的 UI 状态或行为

### 6. 证据附件
- **截图**: `screenshot-YYYYMMDD-NNN.png`
- **录屏**（可选）: `video-YYYYMMDD-NNN.webm`
- **控制台日志**（如有错误）

### 7. 判定
- **状态**: `PASS | FAIL | UNVERIFIED`
- **判定依据**: 
  - `PASS`: 实际行为符合预期
  - `FAIL`: 实际行为不符合预期，且有可复现的步骤
  - `UNVERIFIED`: 工具不可用或无法完成真实交互验证

### 8. 平台与真实交互要求
- **真实指针要求**: 拖拽操作必须使用真实鼠标指针事件，不得使用合成事件
- **视口要求**: 窄视口测试必须使用固定小视口（如 `375x667`）
- **刷新要求**: 刷新重开测试必须执行整页刷新（F5 或 Ctrl+R），不得使用应用内刷新

## 示例：拖拽场景证据

### 基本信息
- **证据 ID**: `EVID-20260916-001`
- **关联目标**: `g-298`
- **关联候选**: `commit: 1a3d9b6`
- **测试环境**: 
  - 浏览器: `Chrome 120`
  - 视口: `1920x1080`
  - 操作系统: `Linux (WSL2)`
  - 测试实例: `port 3082`

### 场景定义
- **场景类型**: `drag`
- **场景描述**: 从 backlog 泳道拖拽目标到版本泳道
- **前置条件**: 
  - 已创建目标 `g-001`（位于 backlog）
  - 已创建版本 `v1.0`（空版本泳道）

### 操作序列
```
1. 打开看板页面 http://127.0.0.1:3082
2. 找到 backlog 泳道中的目标 g-001 卡片
3. 使用鼠标左键按住卡片不放
4. 拖动鼠标到 v1.0 版本泳道
5. 释放鼠标左键
```

### 预期行为
- 目标 g-001 从 backlog 泳道移动到 v1.0 版本泳道
- 看板自动刷新，显示更新后的位置

### 实际行为
- 目标 g-001 成功移动到 v1.0 版本泳道
- 看板自动刷新，显示正确

### 证据附件
- **截图**: `screenshot-20260916-001.png`

### 判定
- **状态**: `PASS`
- **判定依据**: 实际行为符合预期，拖拽操作使用真实鼠标指针事件

## 使用说明

1. **每个证据条目必须完整填写所有字段**
2. **截图必须包含足够的上下文**，能够清楚展示测试前后的状态
3. **操作序列必须详细**，确保其他人员能够复现
4. **判定必须基于真实交互**，不得使用合成事件或 HTTP 200 作为判定依据
5. **UNVERIFIED 状态必须说明原因**，并列出待负责人手动复核事项
