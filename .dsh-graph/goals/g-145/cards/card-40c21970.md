## 收集结论：当前收集 spawn、绑定与回填路径

### 现状与根因

- REST 收集端点：`dsh-graph-host/index.js` 的 `/api/dsh-graph/start-collection`（约 L747–L776）。它读取 `{ goal, card, prompt, provider, model }`，创建 `agent:collect` attempt、spawn child，再绑定 attempt/card。
- 当前后端回退 prompt 只要求“收集关于 card 的上下文”及 text/summary 写法；缺仓库根、goal/card 的精确 id、卡片 title/kind、精确 `graph_fill_card` 调用模板和禁区。
- GUI 收集草稿 prompt：`dsh-graph-host/lib/client.js` 约 L1047。虽含目标标题和卡片标题，但同样缺 card id/kind、workspace 根与精确回填模板。因此 GUI“开始收集”是独立的漏注入路径。
- `graph_bind_collect_card` → `core/ops.ts::bindCardChild`（约 L849–L874）会幂等写入 `child_id`、`parent_session_id` 与 `collecting`。
- `graph_fill_card` → `core/ops.ts::fillCard`（约 L804–L824）仅验证卡片存在；当前不比对填充者与 card 的 `child_id`，任何 actor 都可填充。

### 最小修复方案

1. 在 REST `start-collection` spawn 前读取当前目标和卡片元数据，构造不可被用户 prompt 替代的结构化上下文；用户填写的 prompt 仅作为附加要求。
2. 注入：仓库根、goal id/title、card id/title/kind、收集范围，以及唯一回填模板：`graph_fill_card(goal="<goal>", card="<card>", text=<全文>, summary=<≤100字摘要>)`。
3. 在 GUI“开始收集”的实际提示词中注入同一字段与禁区，或复用同一个 `formatCollectPrompt`，避免前后端漂移。
4. 明确禁区：不得猜 `.dsh-graph` 路径、不得修改其他 goal/card、不得自行 `graph_review_card`；完成后由 supervisor 复核。
5. 兼容人工/supervisor 回填：`fillCard` 可维持宽松写入，同时在 collecting 卡片由非绑定 child 填充时记录 `card.fill_mismatch` 软事件/警告，供 validate 或测试识别。

### 测试建议

- 在 `core/tests/client.test.ts` 或新增 `core/tests/collect-prompt.test.ts` mock `subagents.startContinuable` 捕获 prompt，分别断言 REST 与 GUI“开始收集”路径均含全部上下文字段、唯一模板、禁区，且保留用户补充 prompt。
- 在 cards/bind-collect-card 测试中覆盖正确回填、错误 goal/card 回填的拒绝或 mismatch 记录，以及人工/supervisor 正常回填不回归。
- 复用 `core/tests/inject-cards.test.ts` 的 prompt mock 模式；全量运行 `node --test core/tests/*.test.ts`。
