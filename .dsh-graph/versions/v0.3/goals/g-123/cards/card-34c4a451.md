# dsh-session 服务 API 调研报告（g-123 / dummy2）

**辨识标记：DUMMY2-VERIFY-G120-9c4e**

调研对象：`@deepseek-ai/dsh-session/lib/index.js`（1890 行，已通读全文，只读未改任何文件）。

## 0. 关键更正：不存在 `query()` 方法
本模块**没有** `query()` 方法（全文仅一处 doc 注释提到 "query" 字样）。会话枚举方法实际叫 **`list()`**。若你的调用方在用 `query()`，它来自别处（如持久化插件或旧版），本服务层应改用 `list()`。

## 1. 公开方法清单

### SessionStore（会话服务本体，`ctx.sessions`，extends cordis `Service`）
| 方法 | 签名 | 说明 |
|---|---|---|
| `create` | `create(id?, options?) → Session` | 创建并 enter + announce，立即进入 store。id 省略时自动铸 `session-<n>`。重复 id 抛错 |
| `prepare` | `prepare(id?, options?) → Session` | 只构造不进入 store（配对 `enter`+`announce` 使用；`seedSource:'persistence'` 走 `Session.fromRestore`） |
| `enter` | `enter(session) → detach disposer` | 装入 store、挂发布钩子；返回 detach 函数 |
| `announce` | `announce(session)` | 发 `session/created` 事件（恰好一次） |
| `detachEntered` | `detachEntered(entry)` | 移除 entry；已 announce 则发 `session/disposed` |
| `emitDisposed` | `emitDisposed(entry)` | 发 `session/disposed` 事件 |
| `flush` | `async flush(session) → boolean` | 派发 `session/flush` 持久化检查点；返回是否有耐久监听者参与，全部 settle 后抛首个失败 |
| `liveEntryFor` | `liveEntryFor(session) → entry` | 取 live entry；非 live 抛错 |
| `get` | `get(id) → Session \| undefined` | 按 id 查 live 会话（不存在的 id 返回 undefined） |
| `list` | `list() → Session[]` | 全部 live 会话，按创建顺序，返回新数组 |
| `fork` | `fork(source, boundary?, childSessionId?) → Session` | 从 live 源会话的稳定前缀 fork 子会话；boundary 为含端点 seq，不得落在 open turn 内；错误码 `SessionForkError`（SESSION_ALREADY_EXISTS / INVALID_BOUNDARY / OPEN_TURN / SESSION_NOT_FOUND / SESSION_NOT_LIVE） |
| `_forkSeed` / `_resolveForkSource` | 私有辅助 | 下划线私有，非公开 API |

### Session（普通类，非 Service；事件溯源会话本体）
- 静态：`Session.create(id, seed?, header?)`（detached 快照模式）、`Session.fromRestore(id, seed, header)`（接管所有权恢复模式）
- 实例 getter：`id`（=header.id）、`events`（不可变事件日志快照，冻结数组）、`seq`（下一事件 seq = 日志长度）、`surface`（SurfaceManager）
- 实例方法：`append(type, data, ...opts) → event`（追加事件；`opts` 含 `surfaceOp`/`sourceEventSeqs`；非 JSON 可序列化或违反 surface 契约即抛错）、`requestHeader() → EpochHeader | undefined`、`requestContext()`、`deriveMessages() → Message[]`（派生 LLM 消息历史，缓存化）、`deriveEventMessage(event)`
- 字段：`header`、`firstLiveSeq`、`log`、`surfaceManager` 等

### 其他公开导出
`SessionId`（branded string 函数）、`SessionPreparation`、`SessionForkError`、`SESSION_FORMAT_VERSION`（=0）、`KNOWN_SESSION_EVENT_TYPES`（约 52 种事件类型）、以及纯函数：`canonicalHeader`、`headerEquals`、`foldRequestHeader`、`foldSurface`、`deriveEventMessage`、`snapshotJsonValue`、`snapshotSessionEvent`、`adoptSessionEvent`、`isJsonValue`、`isSurfaceEvent` 系列、`packChunkRuns`、`decodeStorageRecord`、`interruptedTurnClosers`、`TOOL_NOT_STARTED`/`TOOL_OUTCOME_UNKNOWN`。

## 2. `get(id)` 返回结构（Session 记录关键字段）
`get(id)` 返回一个 **Session 实例**（或 undefined），其关键字段：
- **`id`**：string，会话身份（= `header.id`）
- **`header`**：SessionHeader（见下），detached 且 deep-frozen 的创建元数据，**不进入事件日志**
- **`events`**：冻结的只读事件数组快照（每个事件含 `type`/`seq`/`time`/`data`，可选 `surfaceOp`/`sourceEventSeqs`/`ignorable`），append 后旧快照不增长
- **`seq`**：下一事件序号（= log.length，seq 连续性契约）
- **`surface`**：SurfaceManager（`nodes` = 模型可见表面节点 seq 列表、`replaceGeneration` 替换代数）
- **`firstLiveSeq`**：本进程内首次 append 的 seq（构造种子之前的 seq 是 replay/fork 进来的，不发布 `session/event`）
- **`requestHeader()`**：当前生效的 EpochHeader（request/header 事件折叠结果）

## 3. Session id / header 结构
**id**：`SessionId(id)` 是 branded string（纯编译期 cast，无运行时开销）。省略 id 时 store 铸 `session-<n>`（自增计数器）。

**SessionHeader**（`validateSessionHeader` 强制校验，store 填 `version`/`id`/`createdAt`，其余来自 `options.meta`）：
| 字段 | 类型 | 约束 |
|---|---|---|
| `version` | number | **必须 0**（SESSION_FORMAT_VERSION，写/读双端强制） |
| `id` | string | 必须与会话 id 一致 |
| `createdAt` | number | 非负安全整数（ms 时间戳） |
| `cwd` | string（可选） | 必须绝对路径（存储后端按它建目录） |
| `parentSession` | string（可选） | 父会话 id（fork 血缘） |
| `seedLength` | number（可选） | 非负安全整数，durable fork 血缘边界 |
| `origin` | string（可选） | 若存在必须为 `"subagent"` |
| `delegationDepth` | number（可选） | 非负安全整数 |
| `agentPreset` | string（可选） | agent 预设名 |

注意区分：`session.header`（上面的存储元数据，在事件日志之外）≠ 事件 `request/header` 里的 **EpochHeader**（请求级配置：`config`（含 provider/model/reasoningEffort/maxTokens）、`adapterDefaults`、`system`、`tools`）。
