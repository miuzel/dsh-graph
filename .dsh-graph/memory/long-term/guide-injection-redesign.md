# supervisor 守则注入设计转向（负责人 2026-08-22）

来源目标：g-118。

## 最终设计（否决「自动注入完整守则」）

- **背景**：新会话不调 skill 裸奔自实现 g-117 撑爆会话 → 想自动注入主管守则；
- **负责人否决**：每个会话自动注入 supervisor 角色/完整守则 → 临时会话会**争抢 supervisor**；
- **定案**：
  1. 接管仍显式：`graph_claim_supervisor`（g-117）；
  2. 所有会话注入**简短引导提示词**（~120 字）：告知如何 claim + graph_help 命令存在，
     内容轻量无害、只告知「如何」接管、不授予角色；
  3. 新增 `graph_help` 工具：输出使用说明 + claim 指引（不含完整守则）；
  4. 完整守则仍走显式 `skill dsh-graph-supervisor` 调用，绝不自动注入（含执行子代理）。

## 机制（可复用）

- `ctx.systemPrompt.section({name, order, text: () => HINT})` 恒定渲染所有会话；
  systemPrompt 服务可能晚激活 → 轮询注册（20s 上限），缺失静默跳过（skill 目录兜底）；
- 隔离靠**内容断言**（注入文本不含铁律/不可妥协/主管角色），非 session.id 判定。

## 流程教训

- 设计转向时：目标描述 + 质量判据**必须同步更新**（负责人提醒），att-001 在转向同刻
  按旧设计声明完成 → 打回改造；机制可复用、内容重写即可。
