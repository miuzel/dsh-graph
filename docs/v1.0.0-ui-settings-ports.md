# 候选 UI 端口（设计伪码，不是导出 API）

[依赖证据](<v1.0.0-ui-settings-recon.md>) · [实施顺序 / 裁决](<v1.0.0-ui-settings-plan.md>)。对齐 [g-620](<v1.0.0-public-contract-draft.md>) 的 BoardSnapshot、TrustedContext、capability 与错误语义；不得倒过来要求 g-620 为 UI 改现有磁盘/REST。以下类型仅表达边界，未编译、未实现，不能当跨宿主验证已完成。

## 1. Snapshot 与 view-model

```ts
type Revision = string; // 由存储/adapter 提供的 opaque token，不用 generatedAt 代替 CAS
type GoalView = {
  id: string; title: string; status: string; type?: string;
  placement: { kind: 'backlog' | 'standalone' | 'version'; slug?: string; archived: boolean };
  criteria?: readonly string[]; metadata: Readonly<Record<string, unknown>>;
};
type GoalGroup = {
  key: string; name: string; count: number;
  detail: { state: 'loaded'; goals: readonly GoalView[] }
        | { state: 'notLoaded' | 'loading' | 'error'; diagnostic?: string };
};
type BoardSnapshot = {
  contractVersion: '1.0-draft.1'; revision: Revision; generatedAt: string;
  scopeKey: string; // adapter 选择的 graphRoot 作用域标识，不是进程 cwd 或凭据
  groups: readonly GoalGroup[]; diagnostics: readonly string[];
  modules: Readonly<Record<string, unknown>>;
  extensions: Readonly<Record<string, unknown>>; // 兼容数据保留，不据此授予能力
};
type BoardViewState = {
  query: string; fullText: boolean; includeArchived: boolean;
  expandedGroupKeys: readonly string[]; selectedGoalId?: string;
};
type BoardVM = {
  groups: readonly GoalGroup[]; matchedIds: readonly string[];
  requestDetails: readonly string[]; // 意图，不在 pure reducer 内发请求
};
// deriveBoardVM(snapshot, viewState, messages, presentation) -> BoardVM
```

现有 versions/standalone/backlog 的顺序与 lazy 计数由 DSH 映射器保留；未载入不等于空组，不能显示“零目标”。snapshot 是派生只读值，不写回 Goal；未知 status/metadata 保留并诊断，不归一成 delivered。现 boardPayload 不含上述完整信封，revision 的来源和作用域须随 g-620 冻结，不能宣称当前 REST 已有一致性快照。

view state 只存展开、搜索、选择；scopeKey 改变必须丢弃旧 retained 明细与异步响应，不把另一个 workspace 的数据带入。旧 board-retain 原地修改 data，未来消费 readonly DTO 前须复制输入并做兼容对照，不能静默改变其调用约定。

```ts
type BoardReadPort = {
  read(options: { archived: boolean; scopeKey: string }): Promise<BoardSnapshot>;
  details(groupKey: string, scopeKey: string): Promise<GoalGroup>;
};
type UiIntent = { kind: 'openGoal'; id: string }
              | { kind: 'openExecution'; executionRef: string }
              | { kind: 'openPath'; pathRef: string };
```

intent 只返回给 adapter；不是可直接执行的路由。写命令通过 g-620 应用端口与可信 adapter，UI 不构造 trusted actor/approval，不提供任意 writeFile 或万能可执行 callback。失败/取消/投递未知保留不同结果；组件不乐观制造 delivered。

## 2. 设置 schema、状态与写入

```ts
type SettingValue = unknown;
type FieldSpec = {
  path: readonly string[]; kind: 'string' | 'boolean' | 'integer' | 'enum' | 'stringList';
  labelKey: string; helpKey?: string; nullable: boolean;
  enumValues?: readonly string[]; min?: number; max?: number;
  origin: 'workspace' | 'profile' | 'localUi'; writable: boolean;
};
type SettingsSchemaView = { revision: Revision; fields: readonly FieldSpec[] };
type SettingsSnapshot = {
  scope: 'workspace' | 'profile'; scopeKey: string; revision?: Revision;
  status: 'loading' | 'ready' | 'unavailable' | 'error'; writable: boolean;
  stored: Readonly<Record<string, SettingValue>>;
  effective: Readonly<Record<string, SettingValue>>;
  provenance: Readonly<Record<string, 'workspace' | 'profile' | 'default'>>;
  invalidPaths: readonly string[];
};
type SettingsDraft = {
  baseline: SettingsSnapshot; edits: Readonly<Record<string, SettingValue>>;
  dirtyPaths: readonly string[]; errors: Readonly<Record<string, string>>;
  state: 'clean' | 'dirty' | 'saving' | 'conflict' | 'error';
};
type SettingsPort = {
  read(scope: 'workspace' | 'profile', scopeKey: string): Promise<SettingsSnapshot>;
  save(scopeKey: string, patch: Readonly<Record<string, unknown>>,
       expectedRevision?: Revision): Promise<SettingsSnapshot>;
};
```

FieldSpec 是权威 schema 的展示投影，不建立第二套默认/迁移规则。project.yaml 仍由 readProjectConfig/writeProjectConfig、schema 校验、事件、原子写管理；profile 是 DSH profile authority，不伪装 workspace 配置。workspace 显式值优先，profile 作缺省，再走现有默认；effective/provenance 由权威读路径生成，不能由前端重算出新口径。API 无 revision 时不伪造 CAS；沿用现有语义并标明限制。

必须区分未配置/null、显式 false、显式空串、空列表，以及 prompt 的 default/custom/disabled 三态；不能保存表单时把 effective 默认值回填成显式配置。invalidPaths 只读展示，不把畸形值归一后写回。服务迟到、只读、旧模型不在目录仍应可展示；目录只 advisory。localUi 的刷新/展开/即时显示偏好不送入 project patch。冲突保留 draft，重新读取并要求处理，不自动 force。每字段 set 与 workspace patch 的不同粒度由 adapter 保留，不承诺跨 profile/workspace 原子事务。

## 3. i18n

```ts
type Messages = Readonly<Record<string, string>>;
type I18nView = { locale: 'zh' | 'en'; messages: Messages };
// translate(view, key, params?: Readonly<Record<string, string | number>>) -> string
// pure；无 window/locale service/DOM/订阅；保留现 createTranslator 缺键与插值顺序
```

字典/插值候选可复用；DSH registerI18n、locale 服务订阅、语言变化重渲染保留在 adapter。dgT 与 dgLang 的同源生命周期不能拆成两个 locale store。提示词模板选择仍由现有宿主资产读取路径负责，不把 UI 字典当提示词来源。文本返回不代表可信 HTML，MarkdownText 与 fallback 安全处理另留原组件。

## 4. Capability projection 不是授权

```ts
type HostCapability = {
  status: 'supported' | 'unsupported' | 'unknown'; available: boolean;
  evidence?: { source: string; checkedAt: string; hostVersion?: string };
  limitations?: readonly string[];
};
type Presentation = {
  visibleModuleEntries: readonly string[];
  actions: Readonly<Record<string, { enabled: boolean; reasonKey?: string }>>;
};
// projectPresentation(modules, capabilities, actionRequirements) -> Presentation
```

两个独立输入不得合并成一个布尔：modules 是 project.yaml 的既有功能开关投影，只有显式 false 隐藏模块入口，缺失/畸形照旧显示；runtime capability 按 g-620 缺 key/unknown/unavailable 禁用所需动作并给原因，无关人工/只读看板不受影响。不能用 capability unknown 把整张看板藏掉，也不能用 modules 默认全开推导 execution.start 可用。服务端授权、真裁剪和 Human Gate 每次仍独立执行；UI enabled 不构成权限证明。能力不是宿主版本号比较，也不是浏览器检查到方法名就认定可用。
