## 一、守卫保证什么

> 本守卫保证「登记表声明的未验证结论在**结论列**与**证据列**存在且未被否定」，
> **不保证**「文档任何位置都没有自相矛盾的肯定式表述」——后者无法用文本守卫穷尽，
> 依赖评审与 `scripts/g633-opencode-mcp-probe.mjs` 实测。

具体到 `plugins/opencode/INSTALL.md` 的 §8 实测表（`plugins/{claude-code,codex}` 结构同理）：

| 保证项 | 判据 | 钉住它的用例 |
| --- | --- | --- |
| 每行恰好 **3 列**（项 \| 状态 \| 证据） | `splitRowCols(r).length === 3` | ⑧b-G1（4 列必红）/ ⑧b-G2（2 列必红） |
| `\|` 是**转义字面竖线**，不分列 | 切分前把 `\|` 换成占位符，切完还原 | ⑧b-G0 / ⑧b-G3（含 `\|` 行必红） |
| **结论列**讲的是这条结论 | 锚点 + `rowPattern` 只对第 1 列匹配 | ⑧b-D（锚点藏证据列必红） |
| **证据列**仍在描述「未证实」 | 必须命中 `UNVERIFIED_SEMANTICS` 词族 | ⑧b-c / ⑧b-c2（六种近义否定逐一正负对照） |
| 证据列**不含无条件肯定断言** | `affirmativeClaimIn()` 分句级判定 | ⑧b-c3（默认能/能自动发现/已跑通/事实上…） |
| 顶部 ⇄ §8 ⇄ 登记表三方逐条对应 | `REQUIRED_UNVERIFIED_ANCHORS` 为唯一真源 | ⑧b-N1…N3 / E3–F5 / Y1′/Y2′/X1′/X2′ |

这些是**结构性**判据：表格的列怎么切、每行几列、哪一列说什么，都可以用代码穷尽地确定。

## 二、守卫**不**保证什么（已知边界）

**表格之外**的段落。最典型的真实逃逸（⑧b-e1）：

```text
| `skills/` 被 OpenCode 自动发现 | ❌ **未验证** | 未在本次实测范围内… |   ← 表格完全诚实

> **小结**：skills 已在本地跑通，按目录放置即可生效。                     ← 表格外，自相矛盾
```

整篇文档自相矛盾，而表格级守卫**按设计**判绿。这不是缺陷未修，而是**有意划定的边界**：

- 表格外段落的措辞空间是**整篇自然语言**，不是有限结构。任何词表都能被同义改写绕过 ——
  c（未经确认）、c3（默认能自动发现）、e1（已在本地跑通）三轮都是这个模式。
- 守卫已达约 2k 行 / 48 用例。每补一轮词表，下一轮仍能构造新措辞，成本线性增长而收益趋零。

## 三、发现「表格外肯定式表述」时该怎么办

**不要**再往守卫里加措辞。正确处置：

1. **用探针实测取证**：`TMPDIR=/tmp node scripts/g633-opencode-mcp-probe.mjs`
   （需先 `bash scripts/build.sh` 产出 `dist/`，PATH 里有 `opencode`）。探针输出逐项 `PASS/FAIL`
   与「是否具鉴别力」，是唯一能证明「这条路到底跑不跑得通」的东西。
2. **按实测结果直接修文档** —— 该写「未验证」就写「未验证」，不要写「已跑通」。
3. 若确属新发现的**表格结构**问题（列数、列语义、锚点被搬走），那是结构性判据，**应当**补用例。

换句话说：**结构问题补守卫，措辞问题改文档 + 跑探针。**

## 四、维护提示

- `REQUIRED_UNVERIFIED_ANCHORS` 是本守卫的**唯一真源**：新增真实未验证项必须先登记，
  否则文档里写什么都判绿（未登记项一律判红）。

  这条测试会先红 —— 请连同本文一起更新，而不是删掉它。
