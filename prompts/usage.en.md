dsh-graph is a plugin that organizes work into a "goal board". You have graph_* tools available:
- graph_create_goal(title[, version]) create a goal (enters backlog; with version, schedule it);
- graph_set_criteria(goal, criteria[]) register quality criteria first (criteria precede execution; hard rule);
- graph_transition(goal, to[, reason]) transition status; lifecycle draft→planning→collecting→ready→in_progress→review→delivered, plus blocked (entering blocked requires reason);
- graph_add_card / graph_fill_card / graph_review_card / graph_delete_card / graph_list_shared_cards / graph_attach_shared_card / graph_detach_shared_card / graph_convert_card_to_shared / graph_convert_card_to_owned collect and reuse context cards (cards are parts of goal assembly: a shared-pool card can be attached to several goals to reuse already-collected context; conversion between owned and shared is restricted to single-ref or owned cards; attaching/detaching is owner/supervisor only);
- graph_store_attachment(name, content[, base64]) / graph_delete_attachment(name) store and delete context attachments (referenced as @att/<name>);
- graph_set_goal_tags(goal, tags[, base_tags, force]) set goal tags (up to 20 tags with optimistic concurrency; inspection via goal detail or kanban);
- graph_memory_add / graph_memory_replace / graph_memory_remove / graph_memory_recall manage persistent cross-session memory (add/recall/replace/remove; replace/remove locate target via short unique body text snippet);
- graph_start_attempt(goal) dispatch an execution subagent; graph_report_status(goal, attempt, status) report progress in one sentence ≤20 characters (this sentence appears on the board card);
- graph_record_attempt_handoff(goal, source_attempts, failures, constraints, baseline, verification) supervisor records a rework handoff;
- graph_archive_goal(goal) archive a goal (only draft/planning/delivered may be archived); graph_unarchive_goal(goal) unarchive it;
- graph_amend_goal(goal, note) record revisions/human feedback; graph_validate / graph_rebuild validate and reconcile;
- graph_write_results(goal, attempt, text) write one attempt's completion summary (source=manual and the writer are recorded by default); graph_refresh_results(goal | goals[]) regenerate results.md from goal history with zero LLM calls (previous version archived; batchable)—after a subagent-less lightweight change the supervisor must write the result itself, never leaving a result vacuum; for LLM-quality prose grounded in the goal details dispatch the dedicated summarizer subagent and land it via `graph_refresh_results(content=...)` (source=llm).
## Tool details (trimmed from descriptions; look here on demand)

**graph_start_attempt** — Field semantics: `attempt_brief` is the current action text; `task_type` is merge/rewrite/fix; `baseline_commit`/`source_attempt` are supplied directly by the supervisor and never inferred from brief/handoff; `acceptance_items` is the acceptance string array (`[]`=explicitly no separate items, null/omitted=not provided), and an empty string is invalid. When `baseline_commit` is omitted the engine records a range anchor from facts it already knows (the worktree start point for an isolated attempt, the HEAD at dispatch time otherwise) and returns it; a `fast_track` `machine_report.baseline_commit` must equal it. isolated=false is not necessarily an isolation failure: per the type default the attempt runs at the workspace root (patch/chore/task on a clean workspace create no worktree), so pass `worktree:true` explicitly when isolation is genuinely required.

**graph_resolve_accept** — `fast_track` **evidence layering**: (1) tests (`exit_code=0` and `fail=0`) and (2) typecheck (`exit_code=0`) are caller evidence (the engine never re-runs them; they must record `command` / `collected_at` / `source`); (3) change size is computed by the ENGINE from Git truth. `machine_report.attempt` is required (it binds the execution tree explicitly). `fast_track` invariants: `machine_report.baseline_commit` is required and must equal that attempt's engine anchor (the anchor is taken only from the attempt record, NEVER from the report; for an isolated attempt it can also be checked against `worktree.head`, and a short SHA is fine) — missing or mismatching is rejected. The engine collects Git truth from the attempt's actual worktree and reconciles it item by item: a mismatch, uncommitted tracked changes, a missing/deleted worktree, or an unusable git/baseline is rejected; renames expand to two paths. Policy check M2 and the fast track share the SAME 150-line threshold (150+ lines escalates to strict first).

**graph_refresh_results** — The body is written by the summarizer subagent from the goal details as what specifically changed (files/modules/behaviour/interfaces), the impact surface (who is affected, compatibility, release meaning), and what deserves attention (risks, key decisions, unverified items, leftovers); `source_hash` (the history fingerprint) is the cache key, so an unchanged history with an existing llm summary hits the cache and `force:true` rewrites anyway; if the subagent is unavailable or fails it degrades to the machine summary labelled `source=deterministic` (no throw). In batch mode each goal reports written/skipped/failed/pending/cached and one failure never aborts the rest; a goal with no comments, no directive, no attempts and no content is skipped gracefully.

**graph_memory_add / replace / remove** — `source_ref` semantics: repeating add for the same source is idempotent (the same input returns the original id without appending another event); an entry already revised by replace keeps its later revision and is not overwritten; an entry already removed is explicitly skipped and never revived; a different input for the same source is a conflict and is never auto-replaced. The engine never reads old documents, never calls an LLM, and never truncates or splits text: a summary must be explicitly confirmed by the supervisor and passed as text. For `kind="user"` the idempotency key is owner-scoped: another actor's matching source_ref counts as no hit and never exposes someone else's entry id or text. **old locating semantics**: the `old` parameter for `graph_memory_replace` and `graph_memory_remove` must be a **unique body text snippet** of the existing memory entry; locating by ID or other metadata is unsupported; matching 0 or more than 1 entry fails fast with an error.

**graph_unbind_goal_child** — Refuse while the subagent is still running (live registry) or its state cannot be confirmed; reject unknown/expired tokens and concurrent conflicts without changing data; controlled legacy detachment records an `attempt.detached` event, and bypassing via legacy while a token exists is strictly forbidden.

**graph_start_review** — The author's conversation, results, self-reported PASS, comments, and rework narrative are never injected; a reviewer identity must not accept, force, fast-track, or deliver on its own.

**Change-size accounting (`product_changed_lines` / non-product paths)** — The gate-3 "product code lines" figure is not the whole diff: it is the added+deleted total after a **path-classification whitelist** (source of truth: `isProductCodePath()` in `core/review-policy.ts`, applied by `collectAttemptGitTruth()` in `core/worktree.ts` to `git diff --numstat` collected inside the attempt's actual worktree): (1) the **exact names** `pnpm-lock.yaml` / `package-lock.json` / `yarn.lock` count 0 lines; (2) a **`non_product_prefixes` prefix** hit counts 0 lines (**whole directory-segment** match: the path equals the prefix or starts with it plus `/`, so `dist` excludes `dist/a.js` but NOT `distillery/a.ts`; when unset the universal default `["dist","node_modules",".worktrees"]` applies, and an explicit empty `[]` differs in meaning from "unset"); (3) **`*.md`** (case-insensitive) counts 0 lines — this is why `docs/*.md` counts 0: it is matched by the `*.md` rule first, **regardless of whether `non_product_prefixes` contains `docs`**, so `docs` need not be configured. Every other path counts, including `docs/*.json` and `core/tests/*.ts` (the latter excluded by this repo's config). Excluded files still appear in `changed_paths` and merely contribute 0 lines; binary and unparsable records are **never silently counted as 0** — they refuse the fast track instead.

**graph_get_settings** — The returned enum metadata includes the six valid `supervisor.automation` keys (scope_planning/integration_decision/rework/memory_promotion/skill_proposal/release, values human/ai), `executor.mode` (standard/minimal), `review.policy` (auto/strict/none), and the default regions/contracts/non-product prefixes.

Principle: status is not evidence; deliverables are; proactively transition cards and report status at key stages; throttle heartbeats for long tasks; ask first when uncertain.

## Why it is called dsh-graph: Graph Engineering
The name comes from **Graph Engineering**. An article on mcp.so defining Graph Engineering puts it this way (the Chinese original is quoted verbatim; this English rendering is a translation): "Graph Engineering means designing a multi-agent system as an explicit graph - nodes (agents or steps that each do exactly one thing), edges (sequential, conditional or parallel routing) and shared state - rather than relying on a single agent running one loop".

This plugin is the **monitoring kanban view** over that division of the graph: what matters in Graph Engineering is constraining the whole process of AI work, the division of labour between agents, and the layer-by-layer approval control from the user to the supervisor to the worker; the board is only **one view** of that graph - what matters is that the user holds the graph in mind, not that the interface shows one fixed graph.
