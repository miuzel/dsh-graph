## 必须保留的 DSH facade

- 原工具名、参数、REST shape、鉴权/owner/admit、可信 actor 与 root 解析原样；本轮不改变任何 facade。
- conversation.view / header.actions / sidebar、settings.section / plugins.bundle.config 席位及订阅释放仍由 DSH plugin 接线。
- profile namespace 发现、迟到 remote.settings、connection model directory、workspace→profile→默认读取链仍走现有 adapter。
- dgT/dgLang 的单一 locale 绑定、MarkdownText fallback、session-hooks/live-panel、openPath/会话导航不抽。
- UI module-gate 仍消费 core 同源 modules；真正 tools.restrict/agent 事件裁剪与授权继续由服务端执行。

不能先抽 kanban/复杂 modal：网络、弹窗、全局 React/i18n、持久 UI 状态和 DSH session 地址交织；不能先抽 live/主管条：状态归因与 session 导航不是通用执行语义；不能先抽 settings scope：它是 profile RPC/Cordis 兼容桥而非表单状态。不能引入通用认证/路由框架来“解决”这些耦合。

## 负责人裁决（默认建议）

1. UI 包技术栈/公共 exports：先无框架纯 JS/TS 逻辑，不新增 React 版本或重型框架；组件技术栈后定，不立刻发独立 npm 包。
2. 配置主从：保留现 workspace 显式覆盖 profile 缺省、现默认/迁移权威；不建统一 UI store 持久化第二份配置。新宿主 profile authority 及 revision 缺失策略另批。
3. 跨宿主导航：共享层只产出 intent，DSH 自行验证/解析 opaque reference；不承诺跨宿主 session URL 或打开任意路径。
4. Snapshot revision/schema provenance：随 g-620 冻结来源；当前 UI 草案不改变 REST，不以时间戳补 CAS；adapter/global DTO 扩展字段不落盘。
5. 首提取范围：建议仅 module-gate，再验证双消费者后扩大；alpha/k3 不作为实现来源或已通过的第二消费者。
