## 升级/迁移说明

从 v0.6.1 升级：

1. **无破坏性 API 变更**：所有 `graph_*` 工具、REST 端点与看板行为向后兼容；v0.7 功能（目标类型、判据编辑、配置管理、暂缓等）均为纯增量。
2. **数据格式兼容**：`events.jsonl` 格式与 v0.6.1 兼容，无需数据迁移。v0.7 新增的事件类型（`goal.type_changed`、`criteria.updated`、`goal.directive_set`、`goal.comment_added`、`attempt.handoff.confirmed/superseded` 等）在 v0.6.1 中会被忽略，不影响数据完整性。
3. **配置管理（g-132/g-133）**：新增 workspace 与全局两级配置能力；默认配置即当前行为，未配置时不改变原有体验。

## 已知限制

1. **内层 .dsh-graph 仓库无 remote**：默认仅本地存储，负责人需自行配置 remote 实现云端同步/备份。
2. **客户端单文件产物**：`lib/client.js` 仍是合并后的单文件（由模块化源文件经 `scripts/build-client.sh` 生成）——浏览器加载不支持 ES module 分发。
3. **worktree 隔离限制**：graph_* 工具在 linked worktree 中写 `.dsh-graph` 数据时会解析回主工作树 canonical root；极少数边界场景（worktree 路径含特殊字符）可能有兼容性问题。
4. **process.cwd() 兼容回退仍存在**：无显式 workspace 参数时 `resolveRoot` 仍以 `process.cwd()` 兜底（CLI/headless 场景）；host 在无明确 workspace 时不自动 init 骨架。

## 回退说明

如需回退到 v0.6.1：

```sh
# 1. 降级插件版本
cd <dsh-plugin-directory>
pnpm add dsh-graph@0.6.1

# 2. .dsh-graph 数据兼容性
# v0.6.1 与 v0.7.1 的 events.jsonl 格式兼容，无需数据迁移
# v0.7.1 新增的事件类型在 v0.6.1 中会被忽略（不报错、不影响数据完整性）
```

> 注意：若在 v0.7.1 中已使用新增功能（目标类型、判据编辑、配置管理、暂缓等），回退后相关事件仍存在于 events.jsonl 中但不被 v0.6.1 解析——不影响数据完整性，但对应状态不会显示。
