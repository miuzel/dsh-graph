【Mandatory worktree isolation】This task must be completed in an independent worktree: the dedicated worktree is pre-created by the supervisor, or created by the plugin at dispatch time (prepareAttemptWorktree, with the naming convention .worktrees/g-<goal-number>-att-<NN>, a same-named branch, and the baseline commit of this dispatch as the base); the actual worktree path is given by the attempt record / dispatch brief. **You must never independently create a tree, create a branch, switch branches, or modify branches**. Code changes, tests, and generated files may occur only in that worktree; **main is the read-only published branch, and directly modifying main or another target branch is forbidden; independently bypassing isolation on the grounds of a "simple change" is also forbidden**. After completion, commit in the worktree and wait for supervisor review; the supervisor merges into the current version integration branch (such as <version>-test).
【The cwd fact】Your cwd is the main/integration worktree, not your worktree. The dispatched subagent's shell and file tools start with their cwd at the repository root (the main/integration worktree, i.e. <absolute repository root>), and **not** in the .worktrees/g-<goal-number>-att-<NN> above. This is **expected behavior, not a failure**: board data .dsh-graph/ (goals, cards, event stream) must be written to the main worktree, and moving cwd into the worktree would drift the board root to <worktree>/.dsh-graph and corrupt state, so dispatch does not switch cwd for you. **But a cwd in the main worktree never means you may change code in the main worktree** — tools default to cwd, and an inattentive agent edits the main worktree directly (exactly the shape of the concurrent-crosstalk incidents).
【Where your worktree is / how to verify】The naming convention .worktrees/g-<goal-number>-att-<NN> is resolved relative to the repository root (i.e. your cwd), so you can build the absolute path from it; **you must verify the real path before touching anything**: run `git worktree list` (or graph_list_worktrees) to confirm the worktree path and branch for this goal/attempt, and treat the path in the attempt record / dispatch brief as authoritative. The prompt is a static asset and **does not contain** this dispatch's absolute worktree path (the real path is written only into the attempt record); any path you assume is invalid — always go by the verified result.
【Operating discipline】All code changes, test execution, and `git` commits must happen inside that worktree: `cd <absolute path>` first, or pass `git -C <absolute path>` explicitly on every command (read/write files via absolute paths inside the worktree too; never rely on cwd). **Producing any code change in the main worktree is forbidden** (including uncommitted changes). Board data .dsh-graph/ is still written to the main worktree by the graph_* tools — that is the only write allowed to land in the main tree, and it never justifies editing code there.
【The sole exception】Only when the supervisor explicitly writes `worktree=false` and the reason in this dispatch's attempt brief may the independent worktree be exempted; the supervisor handles small changes such as documentation/long-term memory itself, and subagents may not apply the exception on their own. Even with worktree=false, the main branch remains absolutely read-only; directly modifying main is forbidden.
【Worktree naming convention】Attempt worktrees uniformly follow the .worktrees/g-<goal-number>-att-<NN> convention, and branches use the same suffix (for example g-125-att-03, g-163-att-03), eliminating ambiguity and branch conflicts.
